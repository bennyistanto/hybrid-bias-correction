# `data/`

All inputs, intermediate data, masks, and outputs the framework reads or writes live under this directory. Most subfolders are **placeholders** in the public repo - they exist so the code's hard-coded relative paths resolve, but the heavy data either ships separately (Zenodo) or is generated by running the notebooks.

## What ships in the repo

| Path | Status | What's in it |
|------|--------|--------------|
| [`example_bali/`](example_bali/) | **committed** (~11 MB) | The Bali example bundle: IMERG-L, IMERG-F, CPC-UNI (0.1° and native 0.5°), BMKG stations, land/sea mask. Tutorial entry point. |
| [`mask/aoi/bali_subset.nc`](mask/aoi/) | **committed** | The Bali AOI bounding box used by `config_bali.yml`. |
| `mask/iso3/`, `subset/iso3/` | **partially committed** | Indonesia land masks + admin/region polygons, used by visualisation steps. |

## What does **not** ship (placeholder folders)

These folders contain a README only. The actual files are either on Zenodo, downloaded by `notebooks/01_data_acquisition.ipynb`, or generated by the bias-correction pipeline.

| Path | Source | Read by |
|------|--------|---------|
| [`downloads/`](downloads/) | nb01 (`01_data_acquisition.ipynb`) | nb01 only |
| [`input/`](input/) | nb01 stitches downloads here, **or** unpack the [Zenodo bundle](https://doi.org/10.5281/zenodo.20287846) | nb02 onwards |
| [`output/`](output/) | nb02-nb06 write here | nb03-nb06 chain results between stages |
| [`subset/`](subset/) | nb00 / external boundary downloads | Visualisation overlays only |
| `example_bali/output/` | Generated when you run the Bali example | nb03-nb06 (Bali mode) |

## Configuration tokens

The full path under each subfolder is driven by `config.yml` (Indonesia) or `config_bali.yml` (Bali example). Search either file for `{input_dir}`, `{output_dir}`, `mask_file`, or any of the `*_path` keys to see exactly which file the framework expects in which subfolder.

## Quick orientation

- Adapting to a **new AOI**: run `nb00` (AOI + mask) → `nb01` (download) → edit `config.yml` → run `nb02..06`. See the [Data Preparation tutorial](https://bennyistanto.github.io/hybrid-bias-correction/tutorials/data-preparation.html).
- Reproducing the **Indonesia paper run**: download the Zenodo bundle, unpack into `input/` and `output/`, leave `config.yml` as-is.
- Running the **Bali example**: nothing to download. The notebooks default to `config_bali.yml` and read directly from `example_bali/`.
